# Hentai Reader v3.3.0 开发计划

状态：用户回归发现的双页整屏闪烁、18comic 卡死风险与设置控件污染已完成代码修复；
类型检查、71 项自动测试、生产构建和 `git diff --check` 通过。E-Hentai 与 18comic 指定链接
已在 Chrome 中通过本轮实机回归；4KHD 按本轮约定推迟在线验证，但继续受通用直链站点
回归边界保护。未完成其余发布门槛前不得发布。

受众：开发者与 AI Agent。本计划不属于面向最终用户的 README 内容。

## 版本决策

v3.2.3 不再作为独立发布目标。由于新增动态双页阅读这一项用户可见能力，下一版本
直接定为 v3.3.0。当前源码、`package.json` 和生成脚本已进入 3.3.0 候选状态；README
只描述面向用户的候选功能，真实站点验收未通过前不得把本计划标记为可发布。

## 2026-08-01 回归修复

- 双页：删除结构变化时销毁/重建 PhotoSwipe 的路径。单页与双页统一使用稳定 Spread
  容器，当前图片节点在来源不变时保留；Driver 在同一根实例中同步 holder、计数和索引，
  并在拖动、缩放或过渡结束后才应用结构变化。可靠 Preview 尺寸用于提前判断 E-Hentai
  等站点的横竖比例，减少“先单页、后双页”的迟到重排。
- 18comic：高内存 materialize 阶段由 3 并发降为 1；无需反乱序的图片在网络请求前直接
  跳过；Canvas 导出后立即释放 backing store；已解码尺寸直接进入共享缓存，取消成品 Blob

- 设置面板：关闭、开关、步进和分段按钮显式覆盖 appearance、背景、颜色、边框、阴影与

- 自动验证：71/71 测试通过；构建产物 346.11 kB，gzip 74.03 kB。新增门槛保证结构变化

## 目标

1. 新增默认开启的动态双页模式：在阅读器可用宽度足够且相邻两张图片均为窄幅竖图时，
   自动组成双页；横版宽图、空间不足或尺寸未知时安全显示单页。
2. 建立统一、可取消、前台优先的图片生命周期调度，在保证甚至提高当前图片加载速度的
   前提下限制后台下载竞争。
3. 把跨站 Reader 预取上限统一为前方 5 张、后方 2 张，同时保留适配器覆盖能力；
   v3.3.0 的现有站点均使用公共默认值，不声明站点覆盖。
4. 降低卷轴首屏完整图片突发、LCP 图片等待和布局偏移，改善 4KHD 等直接 URL 站点。
5. 约束 18comic 解码图片的 Blob、Object URL 和卷轴租约生命周期，避免超长章节的
   资源数量随 DOM 无界增长。
6. 修复无限分页静默失败、初始化回滚不完整、控制条无法恢复、设置面板无障碍状态、
   层级冲突和自动播放设置不一致等已审计问题。
7. 参考现有粉色渐变、书本轮廓与 `18+` 识别元素重新设计纯 SVG 图标，提高小尺寸清晰度，
   并显著降低 userscript 内嵌图标体积。

## 兼容性红线

- Gallery Item 的稳定 `key` 和逻辑图片索引仍是跨卷轴、Reader、缩略图和分页的唯一身份。
- 双页只是 Reader 表现层，不改变站点适配器返回的数据，不向适配器暴露 PhotoSwipe 状态。
- PhotoSwipe 包导入、内部字段和自定义内容挂载仍只能存在于 Reader Driver。
- 单页与双页必须复用同一 `ImageLoadService` 任务、缓存和租约；不得因组成双页而重复解析、
  下载、解码或创建 Object URL。
- 直接 URL 站点继续通过 `HTMLImageElement` 加载图片，不统一改成要求 CORS 的
  `fetch -> Blob` 路径。
- 现有桌面滚轮、键盘、点击区域、移动端滑动、双指缩放、垂直关闭和 UI 事件屏蔽语义
  不得回归。
- 任何资源预算不得 revoke 仍由 Reader 或卷轴可见图片持有的 Object URL。
- 站点选择器和 URL 变换只有在真实页面证据与适配器 fixture 同时存在时才可修改。

## 核心设计决策

### 1. 逻辑页与表现页分离

Reader 继续以 Gallery Item 作为逻辑页。新增纯 Reader 层的 Spread/Layout 模型，把一个
或两个逻辑页映射为一个表现页：

```text
GalleryItem[]
  -> ReaderSession（逻辑页、稳定 key、当前逻辑位置）
  -> SpreadLayoutModel（单页/双页表现映射）
  -> ReaderDriver / PhotoSwipe（显示、手势、缩放）
```

- `ReaderSession` 不存 PhotoSwipe 对象，也不依赖站点或全局 Store。
- Spread 使用稳定 key 保存成员；重算布局时通过 key 保持当前阅读位置，而不是保存易失的
  Driver slide index。
- 计数显示逻辑页范围，例如 `12–13 / 200`；单页仍显示 `12 / 200`。
- 缩略图点击任一逻辑页时进入包含该页的 Spread，并把被点击页作为当前主逻辑页。
- 下一页/上一页、滚轮、键盘、点击、滑动和自动播放按 Spread 前进或后退；不会在同一双页
  中再次停留一次。
- 双页整体参与 PhotoSwipe 缩放和平移，但两张图片仍是两个独立图片元素和两份独立租约，
  不通过 Canvas 拼接。

### 2. 动态双页判定

新增持久设置 `doublePageMode`，默认 `true`。开关表达用户偏好；实际是否显示双页由布局
条件动态决定。

候选相邻页按逻辑顺序稳定分组，计划默认使用 `0+1`、`2+3` 的固定配对槽位。这样从缩略图
跳转、前后翻页、尺寸迟到或窗口缩放时不会改变整本图库后续页的奇偶归属。v3.3.0 不增加
“封面单独显示”或左右阅读方向设置；较早逻辑页位于左侧，较晚逻辑页位于右侧。

一组候选只有同时满足以下条件才显示双页：

1. 动态双页开关开启。
2. 两张逻辑页均存在，且自然宽高来自可靠 Gallery 元数据或已加载资产。
3. 两张均为竖图，即自然宽度小于自然高度。
4. 按可用 Reader 高度等比适配后，两张显示宽度与页间距之和不超过可用 Reader 宽度。
5. 当前没有正在进行的缩放、拖动或关闭手势。

以下情况必须显示单页：

- 任一图片为横版或正方形，即宽度大于或等于高度。
- 屏幕/窗口宽度不足，包含横竖屏切换、窗口缩小和移动端视口。
- 邻页不存在、加载失败或可靠尺寸尚不可用。
- 用户关闭动态双页模式。

尺寸未知不能阻塞当前图片。Reader 先显示已可用的单页并继续加载；当相邻页尺寸和字节均
就绪、用户处于交互空闲状态且仍停留在对应位置时，可原位升级为双页。升级必须复用当前
DOM/缓存，不闪空白、不重新下载，也不能在手势过程中改变布局。若第二张失败，当前页保持
可读单页，失败页在成为主逻辑页时继续使用正常恢复流程。

视口改变时重新计算是否满足双页条件，并以当前主逻辑页 key 保持位置。双页退回单页时，
不得跳到另一个成员、重复触发自动播放或改变卷轴关闭返回目标。

### 3. 统一预取范围，保留适配器覆盖

公共默认值统一为：

```text
ahead = 5
behind = 2
```

- E-Hentai、ExHentai、4KHD 和 18comic 在 v3.3.0 均使用该默认值，不声明覆盖。
- `ReaderPrefetchPolicy` 和适配器 `readerPrefetch` 能力继续保留；未来站点只有在真实网络、
  单图成本或限流证据支持时才覆盖默认范围。
- 新站点模板和契约测试必须继续覆盖“未声明时使用 5/2”和“声明时正确覆盖”两条路径。
- 5/2 表示活动表现页之外的逻辑图片预取范围，不是 HTTP 并发数。单页活动时最多涉及
  `1 + 5 + 2` 个逻辑页；双页活动时最多涉及 `2 + 5 + 2` 个逻辑页。

预取按阶段启动：

1. 当前单页或双页中的两张可见图立即以 foreground 启动。
2. 阅读方向的下一张立即进入相邻预取。
3. 当前可见图片完成后，按距离补充前方第 2、3 张。
4. 浏览器空闲且网络条件良好时再补齐有效策略的 5/2 窗口。
5. 大幅跳转释放窗口外租约，并取消尚未开始、且不属于新窗口的后台任务。
6. Reader 关闭、页面隐藏或 Gallery 会话销毁时清理相应后台租约。

非卷轴停留预热也使用同一调度器：第一张可预热；第二张仅在网络良好时预热；其余项目
延后到空闲阶段，不再在固定定时器后无条件同时启动三张完整图。

### 4. 图片生命周期调度

新增跨站图片任务调度层，控制完整图片生命周期的启动顺序，而不是只限制最后一次
`img.src` 赋值：

- 默认总活动图片任务不超过 4，投机/后台任务最多 2，为当前单页或双页保留两个前台位置。
- 当前双页中的两张都属于 foreground；任何一张都不得排在尚未启动的 warm-up、缩略图或
  远端卷轴任务之后。
- 优先级提升必须作用于同一个共享任务，不创建第二条生命周期。
- 直接 URL、viewer 解析和 materialize 站点共享启动纪律；E-Hentai 的站点
  `NetLimiter` 和 18comic 的 CPU materialize 上限继续处理各自协议/计算约束。
- `Save-Data` 开启时停止新增后台完整图任务；`slow-2g/2g` 时降为总 2、后台最多 1；
  API 不可用时使用默认 4/2。不得仅因 `3g` 标签就降低前台并发。
- `document.visibilityState === 'hidden'` 时不新增后台预取；回到可见状态后按最新位置补齐。
- Reader 打开时取消未开始且远离活动位置的卷轴任务；已经完成或仍有其他消费者的共享任务
  不取消。

这里的 4/2 是执行并发，5/2 是空间窗口，两者不可合并为一组数字。

### 5. 卷轴加载策略

- 首张和当前视口正文图使用高优先级；近视口图片使用普通优先级；远端图片保持懒加载和
  低优先级。
- 只有可靠 `GalleryItem.dimensions`、可靠 Preview 尺寸或共享缓存自然尺寸才能用于占位
  几何。4KHD 已证实其静态展示宽高可能与原图比例不同，不得重新发布该不可靠值。
- 未知尺寸继续使用公共安全降级，不为了几何额外下载完整图或缩略图。
- IntersectionObserver 初始保留约 2,000 px 上下边界；在几何和调度完成后用真实 trace
  决定是否缩小，不能只凭请求数量机械收窄。
- Spinner 改为合成友好的 transform 动画，加载/错误状态切换不得改变占位外部几何。
- Reader 打开时卷轴暂停新增图片任务；关闭后只恢复当前视口附近观察。

### 6. 18comic 资源治理

该策略只作用于 `ownsObjectUrl === true` 的图片，不影响 4KHD、E-Hentai 或未来普通直链
站点：

- Object URL 软上限暂定 24 项，受管 Blob 总量软上限暂定 96 MiB；实现必须记录真实
  `Blob.size`，不能用图片尺寸猜测压缩字节。
- 任一上限触发时，优先处理离视口最远且不属于当前 Reader、活动预取或缩略图任务的条目。
- 卷轴仅对所有权型图片保留视口前后约 6 个视口的实体 `<img>`；更远条目恢复为保留已知
  几何的占位元素，释放 DOM 租约后才能进入 LRU 和 revoke 流程。
- 普通远程图片不做上述反虚拟化，避免滚回时重复下载。
- 如果堆快照证明 24/96 仍导致不可接受的增长，才根据数据收紧；如果真实浏览器能稳定回收，
  也不得取消“活跃资源不可 revoke”的所有权红线。

## 实施阶段

### 阶段 0：冻结基线和测试夹具

- 保存 v3.2.2 在 E-Hentai、4KHD 和 18comic 的 Reader/卷轴网络记录与关键指标。
- 建立单页、连续竖图、横图夹竖图、奇数尾页、尺寸迟到和加载失败的本地 Gallery fixture。
- 建立调度诊断统计：活动总数、后台数、排队数、各 intent 数量、任务开始时间和取消原因。
- 建立 18comic Object URL、Blob 字节、租约和离屏 DOM 数量基线。

完成条件：基线可重复，测试不依赖真实站点即可复现主要布局、调度和清理路径。

### 阶段 1：统一预取与图片任务调度

- 把公共预取默认值改为 5/2。
- 删除 E-Hentai 与默认值重复的站点声明，但保留 adapter 覆盖接口和模板能力。

## 自动化测试要求

### Spread/Layout 单元测试

- 两张竖图且空间足够组成双页。
- 任一横图/正方形时对应候选拆为单页。
- 宽度不足、开关关闭、尺寸未知、第二张失败和奇数尾页保持单页。
- 固定配对槽位在跳转、回退和 resize 后保持稳定。
- 双页到单页、单页到双页保留主逻辑 key。
- 缩略图跳到双页的任一成员都映射到正确 Spread。
- 自动播放和所有导航方式不会重复或跳过逻辑页。

### 调度与生命周期测试

- 默认策略为 5/2；无现有站点声明覆盖。
- 模板适配器覆盖值时仍生效，且不会进入 Reader 的站点名称分支。
- 总活动图片任务不超过 4，后台不超过 2。
- 双页两张前台图均能立即取得保留位置。
- 后台任务被前台需求共享时提升同一任务，而不是重复下载。
- 大幅跳转、Reader 关闭、页面隐藏和初始化失败会释放正确租约。
- Save-Data 与 2g 降级符合策略，API 缺失时安全回退。

### UI、分页与资源测试

- 分页失败经过 1/2/4 秒退避后出现可操作错误状态；手动重试只启动一个请求。
- `showControl=false` 可通过 GM 菜单恢复。
- 设置面板关闭时不可聚焦且不出现在无障碍树中。
- 自动播放非法/过小旧值被一致归一化。
- 构建结果中的 `@icon` 使用本地 SVG data URL，且仓库不存在旧 PNG 的生产引用。
- Reader 打开/关闭 20 次后 DOM、监听器、Timer、租约和 Object URL 返回基线。
- 200 张所有权型图片压力测试后 Object URL 不超过 24，非活跃 Blob 缓存回落到
  96 MiB 以内；活跃可见资源不得被 revoke。

## 浏览器与真实站点验收

### 性能门槛

- 顶部 5 秒内启动的正文完整图片请求不超过 4。
- 首张正文图不再是 Low priority。
- 当前单页请求和双页的两张前台请求不得等待尚未启动的后台槽位。
- 快速缩略图跳转后，新当前图片任务在 100 ms 内开始排队执行；有可用前台位置时应立即
  开始网络阶段。
- 三档网络条件下当前图片加载不得劣于 v3.2.2；普通/慢网以中位数改善 15% 为目标，
  未达到时必须提供 trace 解释而不能仅凭体感通过。
- 卷轴 CLS 低于 0.1；非首屏图片不得成为页面 `load` 延迟的主要来源。
- 同一 viewer URL 在卷轴、Reader、双页、预取和缩略图之间无重复完整生命周期。

### 双页功能矩阵

| 场景 | 预期 |
| --- | --- |
| 宽屏 + 两张竖图 + 开关开启 | 显示双页，两张均为 foreground |
| 宽屏 + 任一横图/正方形 | 对应候选显示单页 |
| 窄屏/移动竖屏 | 自动单页，偏好开关仍保持开启 |
| 窗口由宽变窄 | 保持主逻辑页并退回单页 |
| 窗口由窄变宽 | 空闲时原位升级，不能重新下载或闪空白 |
| 第二张加载失败 | 第一张保持可读，失败页沿用正常恢复 |
| 缩略图跳到双页第二张 | 进入正确 Spread，并以该逻辑页作为主位置 |
| 双页缩放/拖动 | Spread 整体缩放，手势期间不重排 |
| 自动播放/键盘/滚轮/滑动 | 每次前进一个 Spread，不重复成员 |
| 双页关闭返回卷轴 | 返回主逻辑页对应元素，不使用表现 slide index |

### SVG 图标门槛

- 当前 PNG 基线为 12,433 字节，Base64 内容约 16,580 字符；新 SVG 的最终 `@icon` data URL
  目标不超过 4 KiB，并相对当前元数据至少减少 10 KiB。
- SVG 源文件不得包含 Base64/外链位图、字体、脚本、动画或无法解释的编辑器元数据。
- 在 16、24、32、48、128 和 512 px 下检查轮廓、`18+`、书页与渐变；16/24 px 允许减少
  次要细节，但核心轮廓和年龄标识必须可辨。
- 在浅色、深色和透明背景上检查边缘，不得出现 PNG 式底色方块、裁切或超出 `viewBox`。
- Chrome、Tampermonkey 管理页、脚本安装页和 README 渲染均能显示；不支持 SVG data URL
  的目标环境必须在发布前明确证据，不能默认保留内嵌 PNG 兜底抵消体积收益。
- 图标替换后的生产构建 gzip 体积不得因编码方式异常增大。

## 发布判定

只有同时满足以下条件才能发布 v3.3.0：

- 所有既有测试和新增测试通过，类型检查、生产构建与格式检查通过。
- 动态双页的布局、导航、缩放、设置、预取和清理门槛全部通过。
- E-Hentai/ExHentai、4KHD 和 18comic 真实站点回归通过。
- 性能指标达到门槛，或者对无法达到的第三方网络波动提供可复现对照并确认无代码回归。
- 18comic 长章节资源受控且不存在活跃 Object URL 被提前回收。
- UI 恢复、无障碍、分页错误和初始化回滚路径通过。
- SVG 图标视觉、兼容性和体积门槛通过，旧 PNG 不再进入生产构建。
- 版本号、生成脚本元数据、README、新站点指南和本计划状态一致。

任一发布门槛未满足时，计划状态只能保持“进行中”或“待验收”，不能因为代码已合入或版本号
已修改而标记完成。
