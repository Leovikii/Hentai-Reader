状态：用户回归发现的双页整屏闪烁、18comic 卡死风险、设置控件污染、慢网双页跳动和
PhotoSwipe holder 孤儿容器均已完成代码修复并通过既有 Chrome 回归。本轮新增的双页滚轮
无阻塞策略、Spread 鼠标点击补偿、重映射锁释放、HUD 聚合、Gallery 扩展空 Slide 和资源完成

## 版本决策

v3.2.3 不再作为独立发布目标。由于新增动态双页阅读这一项用户可见能力，下一版本
直接定为 v3.3.0。当前源码、`package.json` 和生成脚本已进入 3.3.0 候选状态；README
只描述面向用户的候选功能，真实站点验收未通过前不得把本计划标记为可发布。

## 2026-08-01 回归修复

- 双页：删除结构变化时销毁/重建 PhotoSwipe 的路径。单页与双页统一使用稳定 Spread
  容器，当前图片节点在来源不变时保留；Driver 在同一根实例中同步 holder、计数和索引，
  并在拖动、缩放或过渡结束后才应用结构变化。可靠 Preview 尺寸用于提前判断 E-Hentai
  等站点的横竖比例，减少“先单页、后双页”的迟到重排。
- 18comic：高内存 materialize 阶段由 3 并发降为 1；无需反乱序的图片在网络请求前直接
  跳过；Canvas 导出后立即释放 backing store；已解码尺寸直接进入共享缓存，取消成品 Blob
  的第二次预解码。快速滚动离开约 6 个视口时取消未完成卷轴租约，Reader 打开时立即取消
  全部未完成卷轴任务，避免旧位置下载和解扰继续占用前台资源。通用直链站点仍保持总 4、
  后台 2 的网络调度。
- 卷轴资源：所有权型图片改由有界 IntersectionObserver 集合执行约 6 视口外回收，删除
  每次滚动对整页 `.r-img` 的查询和同步几何扫描。
- 设置面板：关闭、开关、步进和分段按钮显式覆盖 appearance、背景、颜色、边框、阴影与
  各交互状态，抵抗宿主全局 `button`/`input` 样式及 `!important` 污染。
- 自动验证：71/71 测试通过；构建产物 346.11 kB，gzip 74.03 kB。新增门槛保证结构变化
  只调用 `syncLayout()`、不会销毁 Reader，以及设置按钮保持宿主样式隔离。

## 2026-08-01 双页稳定性、输入与加载反馈优化（代码已实现）

- 已确认双页关系但第二张尚未就绪时，当前 pending 元素只占 `1px`，会让第一张先近似
  居中；第二张到达后槽位扩张并推动第一张横移。这是 DOM 未重建时仍会出现跳动的直接原因。
- 通用 Reader 使用“待确认双页”表现状态：宽屏且固定配对尚无反证时，从第一帧保留两个
  稳定页槽；网络完成后只填充槽位。横图、失败、关闭开关或宽度不足仍安全拆为单页。
- E-Hentai hath 原图 URL 的受验证路径片段包含文件字节数和原图宽高。该规则只由
  `src/sites/e-hentai/` 解析并输出标准可选尺寸提示；共享加载层和 Reader 不识别 hath
  域名、路径或数字格式。实际解码尺寸始终为最终权威值。
- URL 尺寸提示不增加请求，只能把判型提前到 viewer HTML 返回时，不能覆盖 viewer 响应前的
  未知窗口，因此必须与稳定待确认槽配合，而不能作为唯一修复。
- PhotoSwipe 结构同步需要避开拖动、缩放、主滚动过渡和垂直关闭回弹；不得用强制背景
  opacity 或禁用垂直关闭掩盖竞态。
- 双页不再以成员加载状态阻塞输入：两张均未就绪时仍可通过滚轮、键盘、点击或滑动继续导航，
  稳定双槽、槽内加载动画和聚合 HUD 负责反馈。单页加载边界继续保留 v3.2.2 的落页后停止
  本次滚轮手势语义，避免改变关闭动态双页时的原有手感。
- PhotoSwipe 原生鼠标点击不识别自定义 Spread DOM。补偿逻辑只存在于 Driver，且只处理
  mouse：可见 UI 下图片沿用缩放/点击区语义，pending 槽与中缝沿用背景语义；隐藏 UI 时
  Spread 点击优先走背景恢复路径。touch/pen 继续使用原生 tap，避免重复触发。
- 所有分页 prepend 和 Spread 重映射锁都必须在 `finally` 中释放；关闭操作不受重映射锁
  阻断且保持幂等，避免一次竞态异常永久冻结页码、关闭按钮和缩略图状态。
- HUD 按当前 Spread 全体成员聚合 `error → resolving → switching → downloading → loaded`；
  单个成员完成和 Gallery 分页空闲不得直接隐藏仍在下载的当前图片状态。初始打开、资源完成、
  布局同步和延迟索引复位后都主动刷新一次 HUD。
- 实机确认图片来源在 PhotoSwipe 翻页动画中到达时，旧实现会立即刷新目标 Slide，与移动中的
  holder 竞争并造成短时空容器或后续导航迟滞。来源填充和结构重映射现统一等待动画结束后的
  连续两个空闲帧；过渡期间 HUD 保持加载反馈。触摸设备在当前 Spread 未完整就绪时不自动
  隐藏页码、关闭按钮和缩略图，pending 槽显示可见加载动画而不是纯黑背景。
- 实机进一步稳定复现 Gallery 从 40 张扩展到 60 张后的持久空白：旧路径先替换活动布局，再
  只刷新当前与相邻 Slide，PhotoSwipe 已按旧末页缓存的越界 Content 因此未被清除；前两次
  导航停在旧边界，随后会进入没有 Spread DOM 的空 holder。追加和前插现都在 Session 索引
  调整完成后进入同一空闲帧 `syncLayout()` 路径，统一清理越界缓存并同步 holder、总数和索引。
- 重新导入分页修复构建后，在 E-Hentai `1–2 → 3–4` 又稳定复现第二条独立空 Slide 路径：
  `3–4 / 20` 的活动 holder 为一个零子节点 `pswp__zoom-wrap`，没有图片或 Spread，HUD
  `opacity: 0`，控制台无脚本错误；继续到 `5–6` 可恢复。返回首页时下一 holder 仍为空，证明
  这不是 Gallery 扩展或单纯网络等待。
- 根因是同一资源完成事件先直接调用 Driver 刷新，随后才进入空闲帧布局刷新。PhotoSwipe 的
  公共索引刷新会先移除缓存，再根据可能已过期的 `currSlide` 推断 holder；与主滚动轮换竞争时，
  可销毁正确 Slide 却没有把新内容挂回目标 holder。资源完成现只进入统一调度器；每次新完成
  事件都会重新开始两个完整空闲帧的等待，不会被同帧多资源回调提前累计通过。
- Driver 不再调用 PhotoSwipe 公共索引刷新：屏外目标只失效缓存；前一页、当前页和下一页按
  `currIndex` 对应的固定 holder 位置原位 patch，缺少 Slide/Spread 时只重建该精确 holder，
  当前页重建后同步 `currSlide` 与 active 状态。每次正常 `change` 结束也会防御性校验当前 holder。
  “已加载”同时要求当前 Slide、holder 和 Spread 图片节点真实挂载；资源已到但 DOM 为空时
  HUD 继续显示下载中并保留页码、关闭和缩略图控件，而不是无反馈黑屏。
- 资源竞态修复重新导入后，E-Hentai 初始活动 holder 虽尚无图片，但 HUD 与控件立即可见；
  约 2 秒后前/中/后三个 holder 均收敛为 1 wrapper、1 Spread、2 张完整图片。连续 8 次后退
  和 20 次快速前进期间，活动 holder 始终保留 1 wrapper/Spread；加载中的滚轮手势继续推进，
  可见缩略图可从 `39–40` 远跳到 `29–30`，关闭按钮完成根、wrapper、Spread 与 overflow 清理。
- 同轮实机仍观察到两个次级视觉回退：可恢复源失败会让固定双页短暂显示为连续单页，再在恢复
  后重新合并；`40 → 60` Gallery 扩展会把当前已显示的 `39–40` 图片替换成 pending 槽。二者均
  未再造成空 DOM、透明 HUD 或输入阻塞，但仍违反稳定像素目标。现已让已知/未知竖图在可恢复
  失败期间保留固定 pair 槽，并在同一逻辑页的新 itemData 暂缺 `src` 时保留已挂载图片节点；
  横图、方图、宽度不足仍拆为单页。该最新构建待再次导入复测以上两条路径。

## 目标

1. 新增默认开启的动态双页模式：在阅读器可用宽度足够且相邻两张图片均为窄幅竖图时，
   自动组成双页；横版宽图、空间不足或尺寸未知时安全显示单页。
2. 建立统一、可取消、前台优先的图片生命周期调度，在保证甚至提高当前图片加载速度的
   前提下限制后台下载竞争。
3. 把跨站 Reader 预取上限统一为前方 5 张、后方 2 张，同时保留适配器覆盖能力；
   v3.3.0 的现有站点均使用公共默认值，不声明站点覆盖。
4. 降低卷轴首屏完整图片突发、LCP 图片等待和布局偏移，改善 4KHD 等直接 URL 站点。
5. 约束 18comic 解码图片的 Blob、Object URL 和卷轴租约生命周期，避免超长章节的
   资源数量随 DOM 无界增长。
6. 修复无限分页静默失败、初始化回滚不完整、控制条无法恢复、设置面板无障碍状态、
   层级冲突和自动播放设置不一致等已审计问题。
7. 参考现有粉色渐变、书本轮廓与 `18+` 识别元素重新设计纯 SVG 图标，提高小尺寸清晰度，
   并显著降低 userscript 内嵌图标体积。

## 审计基线

- v3.2.2 的类型检查、57 项测试和生产构建通过；生产脚本为 316.89 kB，gzip 76.43 kB。
- E-Hentai 真实链路的卷轴、Reader、翻页、缩略图、跳转取消、关闭清理和自动播放通过。
- 960 x 1564 卷轴冷加载样本在顶部加载 7/11 张正文图，约 2.5 MB；LCP 8,243 ms、
  CLS 0.168，第一张正文图为 Low priority，LCP 时间主要消耗在图片加载。
- 非卷轴 Reader 打开后会扩展字节预取窗口；大幅跳转取消旧位置任务的机制有效。
- 4KHD 使用直接完整图 URL，不生成 Object URL，也没有公共图片字节并发门控；其完整图
  通常为较大的 `w2500-h2500-rw` 资源。此前在线端到端覆盖不足，v3.3.0 必须补齐。
- 18comic 的解码结果使用受管理 Object URL。卷轴图片长期持有租约时，受租约保护的 LRU
  条目不能淘汰；历史 208 页样本没有出现持续标签页内存增长，但资源数量上限仍不明确，
  因此实施前后都必须以堆快照和长章节压力测试验证。

## 范围

### 本版本包含

- 动态双页布局、设置项、导航、缩略图、计数、自动播放、缩放和跨页协同。
- 统一图片生命周期调度、分阶段 Reader 预取、网络条件与页面可见性降级。
- 卷轴图片优先级、可靠几何占位、远近分级和首屏请求控制。
- 18comic 所有权型资源预算与仅限 `ownsObjectUrl` 图片的离屏释放策略。
- 无限分页的有界退避、错误哨兵和手动重试。
- Reader/PhotoSwipe 和应用初始化失败时的完整回滚。
- 已审计的 UI、可恢复性和无障碍缺陷修复。
- 新 SVG 图标、构建元数据接入、尺寸优化和多尺寸视觉验收。
- 新增单元、集成、架构和浏览器端到端测试，以及三个站点的真实回归。

### 本版本不包含

- 自动猜测任意网站 DOM、分页和防盗链规则的“万能适配器”。
- 普通远程图片的卷轴 DOM 虚拟化；避免因回收后恢复而重复下载。
- Canvas 合成双页大图、服务端拼图或新的图片格式转换。
- E-Hentai viewer 协议、`nl` 节点语义、429/503 冷却规则或站点并发保护的重写。
- 18comic 反乱序算法、章节参数提取和输出质量的改变。
- PhotoSwipe 之外的阅读器引擎替换。
- 与本计划无关的视觉主题重做。
- 包含外部字体、脚本、位图 `<image>` 或运行时动画的复杂 SVG 图标。

## 兼容性红线

- Gallery Item 的稳定 `key` 和逻辑图片索引仍是跨卷轴、Reader、缩略图和分页的唯一身份。
- 双页只是 Reader 表现层，不改变站点适配器返回的数据，不向适配器暴露 PhotoSwipe 状态。
- PhotoSwipe 包导入、内部字段和自定义内容挂载仍只能存在于 Reader Driver。
- 单页与双页必须复用同一 `ImageLoadService` 任务、缓存和租约；不得因组成双页而重复解析、
  下载、解码或创建 Object URL。
- 直接 URL 站点继续通过 `HTMLImageElement` 加载图片，不统一改成要求 CORS 的
  `fetch -> Blob` 路径。
- 现有桌面滚轮、键盘、点击区域、移动端滑动、双指缩放、垂直关闭和 UI 事件屏蔽语义
  不得回归。
- 任何资源预算不得 revoke 仍由 Reader 或卷轴可见图片持有的 Object URL。
- 站点选择器和 URL 变换只有在真实页面证据与适配器 fixture 同时存在时才可修改。

## 核心设计决策

### 1. 逻辑页与表现页分离

Reader 继续以 Gallery Item 作为逻辑页。新增纯 Reader 层的 Spread/Layout 模型，把一个
或两个逻辑页映射为一个表现页：

```text
GalleryItem[]
  -> ReaderSession（逻辑页、稳定 key、当前逻辑位置）
  -> SpreadLayoutModel（单页/双页表现映射）
  -> ReaderDriver / PhotoSwipe（显示、手势、缩放）
```

- `ReaderSession` 不存 PhotoSwipe 对象，也不依赖站点或全局 Store。
- Spread 使用稳定 key 保存成员；重算布局时通过 key 保持当前阅读位置，而不是保存易失的
  Driver slide index。
- 计数显示逻辑页范围，例如 `12–13 / 200`；单页仍显示 `12 / 200`。
- 缩略图点击任一逻辑页时进入包含该页的 Spread，并把被点击页作为当前主逻辑页。
- 下一页/上一页、滚轮、键盘、点击、滑动和自动播放按 Spread 前进或后退；不会在同一双页
  中再次停留一次。
- 双页整体参与 PhotoSwipe 缩放和平移，但两张图片仍是两个独立图片元素和两份独立租约，
  不通过 Canvas 拼接。

### 2. 动态双页判定

新增持久设置 `doublePageMode`，默认 `true`。开关表达用户偏好；实际是否显示双页由布局
条件动态决定。

候选相邻页按逻辑顺序稳定分组，计划默认使用 `0+1`、`2+3` 的固定配对槽位。这样从缩略图
跳转、前后翻页、尺寸迟到或窗口缩放时不会改变整本图库后续页的奇偶归属。v3.3.0 不增加
“封面单独显示”或左右阅读方向设置；较早逻辑页位于左侧，较晚逻辑页位于右侧。

一组候选只有同时满足以下条件才显示双页：

1. 动态双页开关开启。
2. 两张逻辑页均存在；确认双页时自然宽高来自可靠 Gallery 元数据、适配器提供的标准尺寸
   提示或已加载资产，待确认双页允许尺寸尚未到达但不能已有横图/失败反证。
3. 两张均为竖图，即自然宽度小于自然高度。
4. 按可用 Reader 高度等比适配后，两张显示宽度与页间距之和不超过可用 Reader 宽度。
5. 当前没有正在进行的缩放、拖动或关闭手势。

以下情况必须显示单页：

- 任一图片为横版或正方形，即宽度大于或等于高度。
- 屏幕/窗口宽度不足，包含横竖屏切换、窗口缩小和移动端视口。
- 邻页不存在、加载失败，或可靠尺寸已经证明任一成员不适合双页。
- 用户关闭动态双页模式。

尺寸未知不能阻塞当前图片或推迟网络请求。宽屏且动态双页开启时，固定配对若尚无横图、失败
或空间不足反证，Reader 先建立包含两个固定页槽的待确认双页；已有图片直接进入其最终槽位，
另一槽保持透明/loading。相邻页确认竖图后只替换槽内容，不改变当前页外部几何、不重新下载，
也不重建 PhotoSwipe。若尺寸最终证明横图、加载失败或空间不足，则在交互空闲状态安全拆为
单页；不得在拖动、缩放、垂直关闭回弹或主滚动过渡中改变结构。

确认双页和待确认双页都必须为每个成员保留稳定的等分外部槽位；图片在槽内使用 contain，
成员源是否到达不能改变另一个成员的槽位。待确认只是一种 Reader 表现状态，不增加图片
生命周期、租约、下载或适配器站点分支。

E-Hentai 可以在 viewer 解析后从受验证 hath URL 得到可靠原图宽高，并通过通用
`ResolvedImage` 可选尺寸提示发布。这个可选字段只表达“适配器已知的源尺寸”，不表示图片
已经下载或解码，也不得复用 `decodedDimensions` 跳过字节加载。URL 解析、域名/路径约束和
异常值校验全部属于 E-Hentai 适配器；其他站点无需实现该能力。

视口改变时重新计算是否满足双页条件，并以当前主逻辑页 key 保持位置。双页退回单页时，
不得跳到另一个成员、重复触发自动播放或改变卷轴关闭返回目标。

### 3. 统一预取范围，保留适配器覆盖

公共默认值统一为：

```text
ahead = 5
behind = 2
```

- E-Hentai、ExHentai、4KHD 和 18comic 在 v3.3.0 均使用该默认值，不声明覆盖。
- `ReaderPrefetchPolicy` 和适配器 `readerPrefetch` 能力继续保留；未来站点只有在真实网络、
  单图成本或限流证据支持时才覆盖默认范围。
- 新站点模板和契约测试必须继续覆盖“未声明时使用 5/2”和“声明时正确覆盖”两条路径。
- 5/2 表示活动表现页之外的逻辑图片预取范围，不是 HTTP 并发数。单页活动时最多涉及
  `1 + 5 + 2` 个逻辑页；双页活动时最多涉及 `2 + 5 + 2` 个逻辑页。

预取按阶段启动：

1. 当前单页或双页中的两张可见图立即以 foreground 启动。
2. 阅读方向的下一张立即进入相邻预取。
3. 当前可见图片完成后，按距离补充前方第 2、3 张。
4. 浏览器空闲且网络条件良好时再补齐有效策略的 5/2 窗口。
5. 大幅跳转释放窗口外租约，并取消尚未开始、且不属于新窗口的后台任务。
6. Reader 关闭、页面隐藏或 Gallery 会话销毁时清理相应后台租约。

非卷轴停留预热也使用同一调度器：第一张可预热；第二张仅在网络良好时预热；其余项目
延后到空闲阶段，不再在固定定时器后无条件同时启动三张完整图。

### 4. 图片生命周期调度

新增跨站图片任务调度层，控制完整图片生命周期的启动顺序，而不是只限制最后一次
`img.src` 赋值：

- 默认总活动图片任务不超过 4，投机/后台任务最多 2，为当前单页或双页保留两个前台位置。
- 当前双页中的两张都属于 foreground；任何一张都不得排在尚未启动的 warm-up、缩略图或
  远端卷轴任务之后。
- 优先级提升必须作用于同一个共享任务，不创建第二条生命周期。
- 直接 URL、viewer 解析和 materialize 站点共享启动纪律；E-Hentai 的站点
  `NetLimiter` 和 18comic 的 CPU materialize 上限继续处理各自协议/计算约束。
- `Save-Data` 开启时停止新增后台完整图任务；`slow-2g/2g` 时降为总 2、后台最多 1；
  API 不可用时使用默认 4/2。不得仅因 `3g` 标签就降低前台并发。
- `document.visibilityState === 'hidden'` 时不新增后台预取；回到可见状态后按最新位置补齐。
- Reader 打开时取消未开始且远离活动位置的卷轴任务；已经完成或仍有其他消费者的共享任务
  不取消。

这里的 4/2 是执行并发，5/2 是空间窗口，两者不可合并为一组数字。

### 5. 卷轴加载策略

- 首张和当前视口正文图使用高优先级；近视口图片使用普通优先级；远端图片保持懒加载和
  低优先级。
- 只有可靠 `GalleryItem.dimensions`、可靠 Preview 尺寸或共享缓存自然尺寸才能用于占位
  几何。4KHD 已证实其静态展示宽高可能与原图比例不同，不得重新发布该不可靠值。
- 未知尺寸继续使用公共安全降级，不为了几何额外下载完整图或缩略图。
- IntersectionObserver 初始保留约 2,000 px 上下边界；在几何和调度完成后用真实 trace
  决定是否缩小，不能只凭请求数量机械收窄。
- Spinner 改为合成友好的 transform 动画，加载/错误状态切换不得改变占位外部几何。
- Reader 打开时卷轴暂停新增图片任务；关闭后只恢复当前视口附近观察。

### 6. 18comic 资源治理

该策略只作用于 `ownsObjectUrl === true` 的图片，不影响 4KHD、E-Hentai 或未来普通直链
站点：

- Object URL 软上限暂定 24 项，受管 Blob 总量软上限暂定 96 MiB；实现必须记录真实
  `Blob.size`，不能用图片尺寸猜测压缩字节。
- 任一上限触发时，优先处理离视口最远且不属于当前 Reader、活动预取或缩略图任务的条目。
- 卷轴仅对所有权型图片保留视口前后约 6 个视口的实体 `<img>`；更远条目恢复为保留已知
  几何的占位元素，释放 DOM 租约后才能进入 LRU 和 revoke 流程。
- 普通远程图片不做上述反虚拟化，避免滚回时重复下载。
- 如果堆快照证明 24/96 仍导致不可接受的增长，才根据数据收紧；如果真实浏览器能稳定回收，
  也不得取消“活跃资源不可 revoke”的所有权红线。

- 自动播放非法/过小旧值被一致归一化。
- 构建结果中的 `@icon` 使用本地 SVG data URL，且仓库不存在旧 PNG 的生产引用。
- Reader 打开/关闭 20 次后 DOM、监听器、Timer、租约和 Object URL 返回基线。
- 200 张所有权型图片压力测试后 Object URL 不超过 24，非活跃 Blob 缓存回落到
  96 MiB 以内；活跃可见资源不得被 revoke。

## 浏览器与真实站点验收

### 性能门槛

- 顶部 5 秒内启动的正文完整图片请求不超过 4。
- 首张正文图不再是 Low priority。
- 当前单页请求和双页的两张前台请求不得等待尚未启动的后台槽位。
- 快速缩略图跳转后，新当前图片任务在 100 ms 内开始排队执行；有可用前台位置时应立即
  开始网络阶段。
- 三档网络条件下当前图片加载不得劣于 v3.2.2；普通/慢网以中位数改善 15% 为目标，
  未达到时必须提供 trace 解释而不能仅凭体感通过。
- 卷轴 CLS 低于 0.1；非首屏图片不得成为页面 `load` 延迟的主要来源。
- 同一 viewer URL 在卷轴、Reader、双页、预取和缩略图之间无重复完整生命周期。

### 双页功能矩阵

| 场景 | 预期 |
| --- | --- |
| 宽屏 + 两张竖图 + 开关开启 | 显示双页，两张均为 foreground |
| 宽屏 + 相邻页尺寸/来源迟到 | 从第一帧保留双槽，来源到达不移动已显示页 |
| 宽屏 + 任一横图/正方形 | 对应候选显示单页 |
| 窄屏/移动竖屏 | 自动单页，偏好开关仍保持开启 |
| 窗口由宽变窄 | 保持主逻辑页并退回单页 |
| 窗口由窄变宽 | 空闲时原位升级，不能重新下载或闪空白 |
| 第二张加载失败 | 第一张保持可读，失败页沿用正常恢复 |
| 缩略图跳到双页第二张 | 进入正确 Spread，并以该逻辑页作为主位置 |
| 双页缩放/拖动 | Spread 整体缩放，手势期间不重排 |
| 自动播放/键盘/滚轮/滑动 | 每次前进一个 Spread，不重复成员 |
| 双页关闭返回卷轴 | 返回主逻辑页对应元素，不使用表现 slide index |

### SVG 图标门槛

- 当前 PNG 基线为 12,433 字节，Base64 内容约 16,580 字符；新 SVG 的最终 `@icon` data URL
  目标不超过 4 KiB，并相对当前元数据至少减少 10 KiB。
- SVG 源文件不得包含 Base64/外链位图、字体、脚本、动画或无法解释的编辑器元数据。
- 在 16、24、32、48、128 和 512 px 下检查轮廓、`18+`、书页与渐变；16/24 px 允许减少
  次要细节，但核心轮廓和年龄标识必须可辨。
- 在浅色、深色和透明背景上检查边缘，不得出现 PNG 式底色方块、裁切或超出 `viewBox`。
- Chrome、Tampermonkey 管理页、脚本安装页和 README 渲染均能显示；不支持 SVG data URL
  的目标环境必须在发布前明确证据，不能默认保留内嵌 PNG 兜底抵消体积收益。
- 图标替换后的生产构建 gzip 体积不得因编码方式异常增大。

### 站点回归矩阵

| 站点 | 必测重点 |
| --- | --- |
| 4KHD | 直接 URL、首屏请求、双页、URL 缩略图、无限分页、镜像域名 |
| E-Hentai | viewer 限流、5/2 默认、`nl` 切换、双页、普通/Sprite 缩略图、跨页 |
| ExHentai | 登录态、viewer/`nl`、双页、跨页和关闭 URL 同步 |

移动端真实手势不能只用桌面设备模拟替代。涉及 Driver 或双页内容挂载的实现完成后，必须
人工验证单指翻页、双指缩放、缩放后拖动、垂直关闭、UI 自动隐藏、设置面板和缩略图交互。

## 发布判定

只有同时满足以下条件才能发布 v3.3.0：

- 所有既有测试和新增测试通过，类型检查、生产构建与格式检查通过。
- 动态双页的布局、导航、缩放、设置、预取和清理门槛全部通过。
- E-Hentai/ExHentai、4KHD 和 18comic 真实站点回归通过。
- 性能指标达到门槛，或者对无法达到的第三方网络波动提供可复现对照并确认无代码回归。
- 18comic 长章节资源受控且不存在活跃 Object URL 被提前回收。
- UI 恢复、无障碍、分页错误和初始化回滚路径通过。
- SVG 图标视觉、兼容性和体积门槛通过，旧 PNG 不再进入生产构建。
- 版本号、生成脚本元数据、README、新站点指南和本计划状态一致。

任一发布门槛未满足时，计划状态只能保持“进行中”或“待验收”，不能因为代码已合入或版本号
已修改而标记完成。
