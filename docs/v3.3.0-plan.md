# Hentai Reader v3.3.0 发布计划

状态：发布检查通过。2026-08-02 已完成 E-Hentai、18comic、4KHD 和移动端真实交互回归，
并通过最终自动化与生产构建。

v3.2.3 不再单独发布。由于动态双页是新的用户可见能力，版本直接升级为 v3.3.0。
本文件只保留最终范围和验收门槛；实现细节见 `architecture.md`，已关闭决策见
`history.md`。

## 发布范围

### 动态双页 Reader

- 设置默认开启；只有视口足够宽时才组成双页。
- 逻辑页按固定槽位配对。可靠横图、方图或窄屏会安全拆成单页；可恢复加载失败保留
  `pending-pair` 稳定槽等待恢复。
- 尺寸尚未到达时可预留稳定双槽；来源或尺寸迟到只原位填充，不重建 Reader 根实例，
  不移动已经显示的页面。
- E-Hentai hath URL 的尺寸解析只存在于站点适配器，并通过通用 `sourceDimensions` 契约
  发布；共享 Reader 和加载层不识别站点 URL 语法。
- 页码、缩略图跳转、自动播放、前后分页、关闭返回和预取继续使用逻辑页身份。
- 滚轮、键盘、点击、滑动、缩放和关闭不得被未完成的双页成员阻塞；聚合 HUD 与稳定槽
  必须持续提供加载反馈。

### 图片调度与稳定性

- 公共 Reader 预取范围统一为前方 5、后方 2；保留适配器覆盖契约，但现有站点均不覆盖。
- 图片任务默认总并发 4、后台最多 2；当前页和双页邻页可提升已经存在的后台任务。
- resolve、可选 materialize、字节验证、重试、缓存、租约和 Object URL 回收由统一图片
  生命周期管理，不允许消费者重复下载。
- 单次来源超时同时约束 materialize 和字节验证，但不取消仍有租约的共享生命周期。
- 无限分页使用有界退避和可手动重试的错误状态；卷轴快速移动会释放远离视口的未完成租约。

### 站点与资源治理

- E-Hentai / ExHentai：保留 limiter、429/503 cooldown、串行 hath 节点切换和站点内尺寸解析。
- 18comic：反乱序转换串行执行；Bitmap、Canvas、Blob 和 Object URL 均有明确释放方；
  受管资源采用 24 个 Object URL / 96 MiB Blob 双预算。
- 4KHD：作为标准直链站点使用公共 Reader、预取和加载行为；不采用已证实不可靠的静态展示
  尺寸推断原图方向。
- 新站点只能通过 `SiteAdapter` 提供能力，不得把站点名称分支写进 Reader、加载或 UI。

### UI、触控与图标

- 设置项与悬浮控件使用语义化按钮，包含 aria、inert、焦点恢复和宿主页样式隔离。
- 移动端点击不保留蓝色 tap/focus 底色；hover 样式只在真正支持 hover 的设备启用。
- 触摸端加载 HUD 与 Reader 控件可见性解耦：网络状态不能唤醒或延长页码、关闭按钮和
  缩略图面板，只有用户主动 tap 可以唤醒控件。
- `src/assets/icon.svg` 是 README 与 userscript 元数据的唯一图标源。SVG 不含外链、位图、
  字体、脚本或动画；构建在 percent-encoded 与 Base64 data URL 中自动选择较短者。

## 架构红线

1. 站点适配器是能力提供者；共享 Reader、重试、预取、缓存、租约和 UI 不按站点名分支。
2. PhotoSwipe 包和内部字段只能出现在 Driver；双页重映射保留现有根实例与已解码图片。
3. 每个 holder 只能有一个活动 zoom wrapper；结构更新必须避开手势/动画，并经过连续两个
   空闲帧的稳定门槛。
4. 当前图片、租约持有的缓存项和正在显示的 Object URL 不得被淘汰或 revoke。
5. 不引入无限重试、全图库预下载、普通图片全量 DOM 虚拟化或关闭 Reader 后的持续滚动纠偏。
6. 根 README 只描述已验收的用户功能；内部计划、测试记录和设计理由只放 `docs/`。
