# Hentai Reader v3.2.1 Optimization Plan

Status: completed and accepted on all three supported sites.

## Scope

- Reduce Reader waits caused by stale E-Hentai prefetch work and slow Hath nodes.
- Keep image resolve, retry, cache and ownership inside the shared image lifecycle.
- Double the directional Reader prefetch window without increasing PhotoSwipe's
  retained slide window or 18comic materialization concurrency.
- Replace residual click-to-retry behavior with bounded automatic recovery.
- Fix scroll image and pagination failures that can become permanently stuck.

## Compatibility boundaries

- Reader, scroll, prefetch and thumbnails continue sharing one image task per
  Gallery item.
- Site-specific node metadata remains in adapters; generic timeout, priority and
  cancellation behavior remains in services.
- E-Hentai viewer concurrency and 18comic materialization concurrency are
  configured independently and initially remain at three.
- No parallel node racing, infinite retry, persistent polling or site-name branch
  is added to Reader code.

## Implementation stages

1. Type the image resolve context and forward priority, force and AbortSignal.
2. Add keyed NetLimiter promotion/cancellation and E-Hentai fresh node requests.
3. Add conservative, adapter-declared byte deadlines with immediate node fallback.
4. Expand directional prefetch from 5/2 to 10/4 and refill after page append.
5. Remove unused E-Hentai URL dimension parsing and residual click retry paths.
6. Add bounded automatic recovery for scroll images and Gallery pagination.
7. Run unit tests, typecheck, production build and real-site regression.

## Initial retry policy

- Foreground/neighbor E-Hentai image attempt: 12 seconds.
- Background E-Hentai image attempt: 20 seconds.
- Node timeouts switch immediately without an additional retry delay.
- Repeated `src + nl` candidates are treated as no progress.
- Existing finite resolve, node and plain retry budgets remain the hard upper bound.

## Acceptance

- A foreground E-Hentai image does not remain behind queued warm-up resolves.
- A stalled Hath image switches node within the configured deadline.
- Reader and scroll recovery require no click handler and cannot retry forever.
- Reader prefetch covers ten items in the travel direction and four behind.
- 18comic decode order/concurrency and 4KHD direct URL behavior do not regress.
- E-Hentai does not produce duplicate viewer requests or 429/503 request storms.

## Implementation result

- Resolver context now forwards a generic retry token, priority, force and
  AbortSignal to every adapter; E-Hentai `nl` details stay inside its adapter.
- Adapter-owned `imageRequestQueue` hooks provide keyed promotion and prefetch
  cancellation without adding site-specific methods to the shared runtime.
- E-Hentai byte attempts use 12-second foreground and 20-second background
  deadlines, followed by serial node fallback without an extra delay.
- Reader prefetch is 10 ahead / 4 behind and refills after Gallery pagination.
- Reader pagination and scroll/image failures use bounded automatic recovery;
  click-to-retry behavior has been removed.
- Site request concurrency and timeout policy live in each adapter; shared
  configuration contains only cross-site settings.
- Fixed/default scroll behavior is declared through generic `scrollPolicy`, so
  the entry point and settings UI never branch on a supported site name.
- The unused E-Hentai URL dimension parser has been removed.
- Typecheck, 50 unit tests and the production build pass.
- E-Hentai/ExHentai, 18comic and 4KHD passed post-cleanup real-site smoke tests;
  no new functional issue was found.
