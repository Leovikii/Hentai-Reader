# Hentai Reader v3.3.1 开发计划

状态：候选实现、自动化验收与真实 Chrome 桌面交互验收已完成。TypeScript、114 项测试、
正式构建和 `git diff --check` 已通过；v3.3.1 userscript 为 374,028 字节，gzip 79.55 kB。
Firefox 与真实触摸手势回归仍是发布前门槛。本版本处理自动播放间隔与阻塞恢复、动态双页排列
方向，以及 E-Hentai viewer 挂起请求的有界超时；不扩展 Reader 导航或图片生命周期所有权。

## 目标与范围

1. 自动播放间隔默认 5 秒，加减按钮由每次 1 秒改为每次 5 秒；保留 1–60 秒的手动整数输入，运行中的
   自动播放在提交新值后立即按新间隔重新计时。1 秒是输入、按钮、持久化读取和实际 timer 的
   统一硬下限，0 或负值都不能成为有效设置。正常间隔结束后若当前页仍未完整显示，只追加一次
   固定 5 秒宽限，随后继续翻页，不能被永久 pending 的图片阻塞。
2. 新增持久化的动态双页排列方向，默认保持当前左到右（LTR）：较早逻辑页在左、较晚逻辑页
   在右；可切换为日漫右到左（RTL）：较早逻辑页在右、较晚逻辑页在左。该设置行只有动态双页
   总开关开启时才展示，单页模式不显示无意义的排列选项。
3. 方向选项只改变一个双页 Spread 内两张页面的展示位置。Spread 序列、单页显示、PhotoSwipe
   导航、左右点击、方向键、横向滑动、滚轮、自动播放、缩略图、分页、预取和关闭返回全部保持
   v3.3.0 逻辑，避免为展示功能改造 Reader 基础组件并引入额外回归。

以下不在本版本范围：按站点自动猜测排列方向、除 viewer 请求超时外修改站点适配器、反转 Gallery 或 Spread 序列、
改变固定 0+1、2+3 配对、改变任何输入/导航语义、引入 PhotoSwipe 分支或补丁、扩大预取/缓存
范围，以及重做设置面板。

## 可行性结论

### 自动播放控件与阻塞恢复

手动输入已存在于 `settings-panel.ts`，当前数据范围为 1–60 秒，Store 以毫秒持久化，配置读取和
timer 已有 1,000 ms 下限，活动 Reader 也已在设置变化时重启计时器。因此无需增加新组件：共享
最小值 1、最大值 60 和按钮步幅 5 的常量，把两个按钮改成 ±5 秒，并统一提交边界即可。

旧加载暂停把 `stop/start` 分散在翻页、资源完成、展示图片 load 和布局刷新回调中；真实 Chrome
在一个双页成员长期没有 `src` 时复现了开关仍开启但计时器永久停止。当前方案改为单个 one-shot
timer：设置间隔到期时若 Spread 未完成，只进入一次 5 秒宽限，宽限到期无条件前进。加载和布局
事件不再负责恢复 timer，避免恢复竞态和重复重置。

“步幅 5 秒”只约束加减按钮，不把手动输入限制为 5 的倍数。例如手动输入 7 秒是有效值，之后
点击加号得到 12 秒。减号到达 1 秒后保持 1 秒，绝不显示或保存 0；有限越界数值按 1–60 秒边界
收敛，空值和非数字恢复最近的有效值。这样同时满足快速调整和精确输入，也避免 HTML `step=5`
与非倍数手输值产生原生校验冲突。

### 动态双页排列方向

本版本把该设置严格定义为“双页排列方向”，而不是对 Reader 导航或 PhotoSwipe 手势做 RTL
改造。固定配对和 `ReaderSpread.logicalIndices` 保持升序；逻辑页、Spread、缓存、分页和预取
顺序都不变。只有包含两个成员的 `.hr-reader-spread` 根据通用方向标记选择 `row` 或
`row-reverse`，并用方向对应的样式让左右图片继续朝书脊对齐。

方向值通过已有 Reader item data 传到展示 DOM；Driver 只渲染通用标记，不读取 Store、不决定
方向，也不修改 PhotoSwipe 索引。运行中改变设置时复用现有 `refreshSlide()`/原位 patch 路径更新
当前 Spread 的标记和对齐，不调用新的底层 API，不销毁根实例，也不触碰手势实现。单页 Spread
忽略该标记，因此横图、窄屏回退和奇数尾页没有行为变化。

该方案改动小、职责单一。RTL 下只会看到较早页位于右侧；点击、方向键和滑动仍保持 v3.3.0
行为。设置名称和文案必须使用“动态双页排列方向 / Two-page Layout”，避免暗示输入方向也会反转。

## 实现阶段

### 阶段 1：设置模型与自动播放步幅

- 在 `UserSettings` 增加 `doublePageDirection` 联合类型，使用独立、可验证的持久化值；缺失
  或非法旧值回退为 `ltr`，保证升级用户行为不变。
- 复用设置面板现有分段控件样式，增加“左到右 / 右到左”排列按钮及中英文文案。排列设置行
  只在 `doublePageMode` 开启时渲染或显示；用户关闭动态双页后立即隐藏，重新开启后立即恢复，
  但隐藏期间不能清除已保存选择，也不能留下可聚焦或被辅助技术读取的隐藏控件。
- 可见性只取决于动态双页总开关，不取决于当前 Spread 是否因窄屏、横图、尺寸未知或奇数尾页
  暂时回退为单页；否则设置行会随翻页或 resize 反复出现和消失。
- 抽取自动播放秒数的默认值、边界和步进规则；默认 5 秒，按钮使用 ±5，手输接受 1–60 的整数，
  点击输入区会全选当前值以便直接覆盖，并支持 change、失焦和 Enter 提交。减到下限后保持 1，
  0/负数收敛为 1；每次有效提交只写一次 Store。
- 确认配置加载、活动自动播放更新和 timer 仍有 1 秒兜底，且只有一个 one-shot timer；无效输入
  不得产生 `NaN`、0 秒循环或多重 timer。加载宽限固定为 5 秒且每页最多一次。

### 阶段 2：展示层排列

- 不修改 `SpreadLayout` 的固定配对、Spread 数组、索引映射、primary 或 key；只在 Reader 生成
  item data 时携带 `doublePageDirection`，并由 Driver 输出/更新通用 DOM 标记。
- CSS 根据标记切换双成员容器的排列方向，并覆盖首尾成员的 `object-position`，保证 LTR 和 RTL
  都朝书脊对齐；pending/失败槽随对应逻辑页一起换边。
- 运行中切换只刷新当前展示内容，沿用现有空闲帧和 `refreshSlide()`/patch 路径；不得新增
  PhotoSwipe 内部访问、调用 `syncLayout()`、重建根实例、重建图片任务或改变当前逻辑页。
- 单成员容器在两个方向下必须完全一致，不得让横图、窄屏回退或奇数尾页发生位置变化。

### 阶段 3：版本与发布资料

- 候选实现完成后把 `package.json`、lockfile 与 userscript 元数据升级为 3.3.1；真实 Chrome
  验收通过后再把已验收功能写入根 `README.md`、`README.zh-CN.md`。
- 发布时把仍有效的方向边界合并进 `architecture.md`，把结果压缩进 `history.md`，并按文档维护
  规则关闭本活动计划。

## 自动化验收

新增或扩展测试必须覆盖：

- 自动播放输入边界、空值、非数字、整数规范化、±5 步进、非 5 倍数手输、1 秒下限和 60 秒
  上限；0/负值最终为 1 秒，设置变化后 timer 只有一个且采用新间隔。未加载页只追加一次 5 秒
  宽限，宽限内即使继续 pending 也必须前进。
- 缺失或非法方向设置回退 LTR；LTR DOM 和样式与 v3.3.0 一致，RTL 只交换 pair 的左右位置。
- `doublePageMode=false` 时排列设置行不可见、不可聚焦且不进入可访问性树；重新开启后恢复之前
  保存的值。当前 Spread 的单双页状态和 viewport resize 不得自行改变该行可见性。
- 固定 pair、Spread 序列、奇数尾页、横图拆分、pending/失败 pair、逻辑映射和计数不因方向改变。
- 运行中 LTR/RTL 切换保持当前稳定逻辑页，每个 holder 仍最多一个 zoom wrapper，已有图片节点
  和已解码像素可复用，不调用 `syncLayout()` 或重建 PhotoSwipe。
- 既有点击、方向键、横向滑动、滚轮、自动播放、缩略图、逻辑首尾和前后分页测试在两个设置值
  下结果一致，证明展示方向没有渗入导航逻辑。
- 架构测试继续禁止 Reader/Driver 读取具体站点、站点写 Store、PhotoSwipe 内部访问扩散和
  方向判断进入适配器、图片服务、滚轮、分页、自动播放或 PhotoSwipe 导航。

每轮实现至少全部成功：

```text
npm run typecheck
npm test
npm run build
git diff --check
```

## 真实交互验收

| 场景 | 发布要求 |
| --- | --- |
| LTR 回归 | Chrome、Firefox 下双页排列、点击、方向键、滑动、滚轮、自动播放与 v3.3.0 一致 |
| RTL 双页 | 较早页在右、较晚页在左，两页仍朝书脊对齐，pending/失败槽位于对应逻辑页一侧 |
| 导航隔离 | LTR 与 RTL 的点击区、方向键、横向滑动、滚轮、缩略图和自动播放结果完全相同 |
| 动态布局 | 奇数尾页、横图、窄屏、尺寸迟到、pending 和失败恢复不改变当前逻辑内容或单页位置 |
| 分页边界 | 两种排列设置都沿用既有 next/prev 逻辑，连续跨页不跳图、不重复请求 |
| 自动播放 | ±5 秒调整和任意 1–60 整数手输即时生效；0/负数收敛为 1；未加载页最多额外等待 5 秒 |
| 触摸端 | 两种排列设置下既有滑动方向、缩放、垂直关闭、tap 唤醒和 UI 自动隐藏不回归 |
| 设置面板 | 关闭双页后排列行立即隐藏且不可聚焦，重开后恢复原值；桌面与移动布局、aria 和焦点正常 |

设备模拟可用于布局压力测试，但不能替代双指缩放、横向滑动和垂直关闭的真实触摸回归。

### Chrome 候选验收结果

- 在 E-Hentai 184 页真实图库中验证 LTR/RTL 双页几何与书脊对齐；RTL 下较早逻辑页位于右侧，
  方向键、左右点击和滚轮仍按既有逻辑前进或返回。375×829 窄视口安全回退单页，方向标记归一
  为 LTR，没有改变 Spread 序列或导航。
- 自动播放间隔验证 `7 → 12 → 7`、`0 → 1`、负数归一为 1，且下限处继续减仍保持 1。双页关闭
  后方向行具有 `hidden`、`inert` 和 `aria-hidden`，重新开启后恢复先前 RTL 选择。
- 针对实机反馈补强输入区的宿主样式隔离和编辑交互：无持久化值时显示默认 5，点击数值会获得
  焦点并全选，直接键入 7 或 12 后 Enter 均可提交；输入 0 仍归一为 1，移动端发布数字键盘提示。
- 真实 Chrome 计时验证：1 秒设置且内容永久 pending 时约 6012 ms 前进；内容已加载时重置后
  约 1013 ms 前进。E-Hentai viewer 请求另有前台 12 秒、后台 20 秒单次超时，避免挂起请求永久
  占用站点 limiter 槽位。
- 桌面精细指针在 375×829 窄窗口发现并修复设置浮层左侧裁切。最新版源码在真实 Chrome 中复测
  面板边界为左 16 px、右 356 px、宽 340 px，无横向溢出；关闭重开后定位与方向状态均保持。

## 发布完成判定

- 本版范围均实现且通过全部自动化与真实交互验收，没有共享层站点名称分支、导航改造或 PhotoSwipe
  根实例重建。
- 默认 LTR 的升级路径无行为变化，非法持久化方向值安全回退；RTL 只交换双页成员展示位置，
  运行中切换不丢失逻辑页身份。
- 自动播放控件的 5 秒步幅、1 秒硬下限和手动输入行为与文案一致，没有 0 秒、多 timer、永久
  加载阻塞或越界持久化。
- 版本号、构建产物和发布说明一致，工作树不包含诊断代码、临时 fixture 或未归档计划。
